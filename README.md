# chr15q14

This repository contains the snakemake workflow and scripts for the analysis of the GOLGA8A repeat expansion using long read sequencing. The workflow provided here is currently intended to document our analysis, and will require some tweaking to be used by others.

## Installation

The workflow uses snakemake, which can be installed with conda/mamba:

```bash
conda create -c conda-forge -c bioconda -n snakemake snakemake
conda activate snakemake
```

The workflow will automatically create conda environments (from yml files in `envs/`) to install the necessary software and run reproducible analysis. These environments are created the first time the workflow is executed, and will only take a few minutes.
The workflow should work on any unix-like system, please let me know if you encounter issues.

## Usage

The workflow, `workflow/chr15q14.smk` uses a tab separate file to describe the whole cohort. This file contains sample identifiers and can as such not be publicly shared. The 1000 Genomes Project part of the cohort description file is avialable in `data/1000G_cohort.tsv`. 
The workflow starts from aligned cram files (generated by minimap2), and uses [STRdust](https://github.com/wdecoster/STRdust) to genotype the STR(s) of interest. STRdust an operate on remote files (in this case from the 1000 Genomes Project) using a URL rather than a local file. Figures are created as part of the workflow with scripts in `scripts/`. Additional figures are generated using jupyter notebooks in `notebooks/`.

The workflow file still needs to be adapted to the local setup of users, as its main goal is to document our analysis. 
Please edit the paths at the top of the workflow file for the `outdir`, `ref`, the excel sheet with samples and `local_cram_path`. In the rules the path to the STRdust binary and aSTRonaut script has to be adapted (params of `rule strdust`, and rules mentioning `aSTRonaut`). Please open an issue if anything is unclear. I am definitely willing to make this easier to use for others, but it is not something I currently foresee will be a frequent occassion.
The snakemake workflow is executed as below, with `--cores` adapted to what is appropriate for your system. The workflow should complete in a few minutes, depending on the degree of parallelization you enabled with `--cores`.

```bash
snakemake -s workflow/chr15q14.smk --use-conda --cores 24
```
